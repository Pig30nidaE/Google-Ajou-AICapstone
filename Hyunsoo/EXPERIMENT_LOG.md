## 3. "MMSE 제외 + GroupKFold" 아이디어 및 numpy 전용 프록시 실험 (이전 단계)

샌드박스에 sklearn/lightgbm/shap 등 ML 라이브러리가 전혀 설치되어 있지 않고 인터넷도 차단된 환경이라,
numpy/pandas만으로 로지스틱회귀+SMOTE+StratifiedKFold/GroupKFold를 처음부터 구현해서 검증함.

- 원본 파이프라인 재구현 검증: `nia+003@rowan.kr` 샘플 값이 노트북 원본과 정확히 일치 → 파이프라인 신뢰도 확인
- 새 피처 아이디어 3종 구현:
  1. **Circadian rhythm 피처**: IS(Interdaily Stability), IV(Intradaily Variability), RA(Relative Amplitude), L5(최소활동 5시간), M10(최대활동 10시간) 및 onset 시각 — MET 1분 시퀀스에서 rolling mean으로 계산
  2. **Trend(추세) 피처**: 환자별 일자 순서에 따른 주요 지표(활동량, 수면 효율 등)의 `np.polyfit` 선형 회귀 기울기
  3. **Missingness(결측률) 피처**: `_valid_count` 컬럼 기반 결측 비율
- Baseline(174,222) → Augmented(174,244), 신규 피처 22개(circadian 8 + trend 10 + missingness 4)
- numpy 로지스틱회귀 프록시 모델로는 baseline vs augmented 거의 차이 없음(AUC 0.54~0.56), daily-level GroupKFold는 오히려 AUC 0.43으로 chance 이하 — 단, 이는 약한 프록시 모델의 한계일 수 있어 결론을 유보하고 실제 프로덕션 모델(LightGBM+SHAP)로 재검증하기로 함.
- 결과물: `feature_engineering_v42_no_mmse.py` (Google Drive "Claude" 폴더에 업로드, file id `1QOjInr0zvuezPcIX7XYc0gaogV-jZosx`), `univariate_auc_ranking_noMMSE.csv`

## 4. 실제 Colab(LightGBM+SHAP) 검증 결과 — ★가장 최근/신뢰도 높은 결과★

**방법**: V26 노트북을 Drive에 사본 저장(`V26_Binary_SOTA_Optimization.ipynb의 사본`,
`https://colab.research.google.com/drive/1qtJTT0DZCB7GrDy2X5Hix6TcrSz9SEJ0`) 후, gustn1686@gmail.com 계정으로
전체 셀 실행 → 신선한 baseline 재현 확인 → 아래 새 셀을 추가해 baseline `df`(patient_level_all_v2.csv, MMSE 없음)에
circadian/trend/missingness 22개 피처를 병합한 `df_aug`를 만들고, 노트북에 이미 정의된
`perform_shap_forward_selection()` / `run_sota_binary_ensemble()`을 동일하게 재사용해 비교.

### Baseline (원본 15개 SHAP 선택 피처)
| 모델 | Acc | Recall | ROC-AUC |
|---|---|---|---|
| LightGBM | 0.7356 | - | 0.7638 |
| CatBoost | 0.7471 | - | 0.7594 |
| XGBoost | 0.7414 | - | 0.7457 |
| RandomForest | 0.7184 | - | 0.7038 |
| **Ensemble** | 0.7299 | 0.7302 | **0.7775** |

### Augmented (증강 피처 포함 pool에서 SHAP이 11개 선택 — 신규 피처는 0개 선택됨)
| 모델 | Acc | Recall | ROC-AUC |
|---|---|---|---|
| LightGBM | 0.6839 | - | 0.7433 |
| CatBoost | 0.7126 | - | **0.7788** (baseline 대비 개선) |
| XGBoost | 0.7126 | - | 0.7296 |
| RandomForest | 0.6552 | - | 0.6951 |
| **Ensemble** | 0.6839 | **0.8413** | 0.7605 (baseline 대비 하락) |

**핵심 결론**:
- SHAP forward selection이 22개 신규 피처(circadian/trend/missingness) 중 **단 하나도 선택하지 않음**
- 최종 앙상블 AUC는 0.7775 → 0.7605로 **하락**, 다만 CatBoost 단일 모델 AUC는 개선(0.7594→0.7788)
- 앙상블 Recall은 0.7302 → 0.8413으로 크게 상승 (정밀도-재현율 트레이드오프 이동)
- numpy 프록시 실험의 "새 피처 효과 미미"라는 결론이 실제 프로덕션 모델(LightGBM+SHAP)로도 재확인됨
- 결과는 Colab 노트북 사본에 저장 완료 (Ctrl+S 저장됨)

### 사용한 셀 코드 (재현용)
로컬에 저장됨: 이 대화의 outputs 폴더 `colab_augmented_cell.py` (Claude Code 세션에는 없을 수 있음 —
필요시 아래 로직을 재구현하면 됨):
1. `load_inputs()`로 원본 train/val activity/sleep/label 로드 (노트북에 이미 정의된 함수 재사용)
2. train+val 병합 후 `make_daily_table()`로 일별 테이블 생성 (노트북 함수 재사용)
3. `activity_met_1min` 원본 시퀀스로 circadian 피처(IS/IV/RA/L5/M10 등 8개) 계산
4. 일별 테이블에서 주요 지표의 `np.polyfit` 선형 기울기(trend, 10개) 계산
5. `*_valid_count` 컬럼 평균으로 missingness 피처(4개) 계산
6. baseline `df`에 EMAIL 기준 병합 → `df_aug` (174, 244)
7. **주의**: SMOTE가 NaN을 허용하지 않으므로 신규 피처의 NaN은 반드시 중앙값(median)으로 대체 후 진행해야 함
8. `perform_shap_forward_selection(df_aug, raw_features_aug)` → `run_sota_binary_ensemble(df_aug, opt_features_aug)`

## 8. Daily-level GroupKFold를 실제 LightGBM/CatBoost/XGBoost/RF로 재검증 (2026-07-27)

**배경**: 이전 세션(numpy 전용 샌드박스)에서는 daily-level(환자당 하루 = 1행, 총 12,150일) 데이터에 GroupKFold(환자
단위로 fold 분리, 데이터 유출 방지)를 적용했을 때 numpy 로지스틱회귀 프록시 모델로 AUC 0.43(랜덤보다 낮음)이 나와
결론을 유보했었음. 이번엔 실제 프로덕션급 모델(LightGBM/CatBoost/XGBoost/RandomForest)로 동일한 실험을 재현.

**방법**: `make_daily_table()`로 만든 환자-일 단위 원본 daily 테이블(174명, 12,150일, 109개 원시 피처, 환자당
평균 70일)에 `StratifiedGroupKFold(group=EMAIL)`을 적용해 SHAP forward selection(16개 피처 선택)과 4개 모델
앙상블을 그대로 재현. 같은 환자의 날짜가 train/test에 동시에 섞이지 않도록 보장.

**결과**:
| 모델 | Day-level AUC (하루 단위 예측) | Patient-level AUC (환자별 일별 확률 평균 재집계) |
|---|---|---|
| LightGBM | 0.5498 | 0.5703 |
| CatBoost | **0.5756** | **0.6110** |
| XGBoost | 0.5584 | 0.6095 |
| RandomForest | 0.5415 | 0.5730 |
| Ensemble(40/20/20/20 고정 가중치) | 0.5566 | 0.5873 |

**해석**:
- numpy 프록시의 AUC 0.43(chance 이하)은 **프록시 모델 자체의 한계**였음이 확인됨 — 실제 트리 모델들은 day-level에서도
  chance(0.5)보다 뚜렷하게 높은 AUC(0.55~0.61)를 보여, daily 데이터에 신호가 아예 없는 것은 아님.
- 그러나 day-level 예측을 환자 단위로 평균 재집계해도 최고 AUC는 0.611(CatBoost)로, **기존 patient-level
  mean+std 사전집계 방식(SOTA baseline AUC 0.776~0.81)에는 크게 못 미침**.
- 앙상블(0.587)이 개별 최고 모델(CatBoost 0.611)보다 낮은 것도 특징 — 기존 40/20/20/20 가중치가 patient-level
  기준으로 튜닝된 것이라 daily-level에는 맞지 않음 (LightGBM·RF가 day-level에서 특히 약함).
- **결론**: 왜 patient-level 집계가 더 나은가 — 인지기능 진단은 하루 단위로 변하는 상태가 아니라 장기간에 걸친
  안정적 특성(trait)에 가깝기 때문에, 개별 하루의 활동/수면 데이터는 노이즈 대비 신호가 약함. 환자별 ~70일을
  mean/std로 요약하면 이 노이즈가 상쇄되고 안정적인 개인 특성이 부각되어 예측력이 높아짐. 즉 **V26의 patient-level
  집계 설계가 daily-level보다 우수하다는 것이 실제 모델로도 재확인됨** (numpy 프록시 결과의 방향성은 맞았으나
  절대 수치(chance 이하)는 프록시의 한계로 과도하게 비관적이었음).

## 12. Nested CV 검증 — ⚠️ 지금까지의 baseline AUC가 대부분 leakage였음을 확인 (2026-07-27)

**배경**: V26(및 이를 그대로 계승한 V29/V35, 오늘의 Optuna 튜닝)의 파이프라인은 SHAP forward selection을
**174명 전체 데이터로 딱 한 번** 계산해 피처(예: 15개)를 고정한 뒤, 그 고정된 피처셋으로 5-Fold CV를 돌려
성능을 보고합니다. 이 SHAP 랭킹 계산 시점에 이미 "5-Fold CV에서 test로 쓰일 환자들"의 정보가 피처 선택에
스며들어 있어(leakage), 보고된 AUC가 실제 일반화 성능보다 부풀려졌을 수 있다는 우려가 제기됨.

**검증 방법**: 제대로 된 Nested CV로 재평가.
- **Outer 5-fold**: 순수 평가 전용. outer-test(35명)는 feature selection, threshold 결정, 모델 학습
  어디에도 절대 사용하지 않음.
- **Inner 5-fold**: outer-train(139명) 안에서만 SHAP forward selection(K=1~40 그리드) + threshold(Youden's J)
  결정.
- 최종적으로 outer-train 전체로 baseline 고정 하이퍼파라미터(LGB/CAT/XGB/RF, 40/20/20/20)의 4개 모델을
  학습해 outer-test에 예측 → 5개 outer fold의 예측을 이어 붙여 174명 전체에 대한 "진짜 held-out" 성능 산출.
- **컨트롤 실험 2회 진행**: (v1) 조기종료(early stopping) 없이 고정 iteration 학습, (v2) outer-test를 전혀
  건드리지 않는 내부 validation split으로 leak-free 조기종료 재현 — 두 버전이 거의 같은 결과를 냈다면
  "조기종료 제거로 인한 과적합"이 원인이 아니라 "feature selection leakage/작은 표본 과적합" 자체가
  원인이라는 뜻이므로 이를 분리하기 위해 실시.

**결과**:
| 방식 | Acc | Prec | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| 기존 (non-nested, SHAP 선택 174명 전체 기준) | 0.7356 | 0.6133 | 0.7302 | 0.6667 | **0.7763** |
| Nested CV v1 (조기종료 없음) | 0.5402 | 0.3836 | 0.4444 | 0.4118 | **0.4921** |
| Nested CV v2 (leak-free 조기종료) | 0.5517 | 0.3913 | 0.4286 | 0.4091 | **0.4690** |

v1/v2가 거의 동일(둘 다 AUC 0.47~0.49)하다는 것은 조기종료 제거 때문이 아니라는 뜻 — outer fold별 AUC도
두 버전에서 패턴이 거의 같음(예: fold2는 v1 0.3636/v2 0.3671로 **랜덤보다도 낮음**, fold5만 v1 0.6705/v2
0.6250로 상대적으로 나음). 5개 fold 중 2개는 랜덤보다 나쁜 예측을 한 것.

**해석**:
- 174명이라는 작은 표본에서 ~220개 후보 피처로 greedy forward selection을 하면, 선택된 피처셋이 우연히
  그 특정 174명(혹은 139명 훈련셋)에 잘 맞는 "노이즈에 과적합된" 조합일 위험이 매우 큼. outer-test를 완전히
  분리하고 나니 이 우연한 적합이 사라지면서 성능이 랜덤 수준으로 붕괴함.
- **지금까지 보고된 모든 "SOTA" 수치(V26 baseline 0.7775, Optuna 튜닝 0.8122, V29/V35 등)는 같은 leakage
  패턴을 공유하므로 전부 같은 문제를 안고 있을 가능성이 높음.** 즉 이 프로젝트가 지금까지 "치매 분류에 성공"
  했다고 믿어온 근거 자체가 재검토되어야 함.
- 다만 완전히 "신호가 없다"고 단정하기도 이름 — outer-train이 139명뿐인 상태에서 40개 피처를 greedy하게
  탐색하는 것 자체가 매우 고분산(high-variance)인 절차라, 이 nested 추정치는 실제 성능의 낙관적 상한이
  아니라 오히려 비관적인 하한에 가까울 수 있음(불안정한 피처 선택 절차 자체의 약점). fold별로 선택된 피처가
  꽤 겹치는 것(`sleep_period_id`는 5개 fold 전부에서 선택, `activity_class_3_count_std`/`sleep_breath_average`/
  `sleep_hr_5min_max_std`는 4개 fold에서 선택)을 보면 완전히 무작위는 아니었지만, 그럼에도 outer-test
  성능은 랜덤 수준이었음.

**다음 단계 제안**:
1. Forward selection을 매 outer fold마다 새로 하지 않고, 더 안정적인 방법(예: L1 정규화 로지스틱회귀로
   피처 선택, 혹은 고정된 소수의 피처만 사용, 혹은 여러 inner 폴드에서 공통으로 뽑힌 피처만 채택)으로
   교체해 nested 성능이 랜덤 수준을 벗어나는지 재확인.
2. Repeated nested CV(예: 5-fold x 5회 반복, 서로 다른 시드)로 이 결과가 우연한 fold 분할 때문인지,
   일관된 패턴인지 확인.
3. V26 report.docx 등 외부에 공유된 "SOTA AUC 0.78" 같은 수치에는 이 nested CV 결과를 반드시 함께
   명시해야 함 — 현재 상태로는 오해를 유발할 수 있음.
- 로컬 스크립트: `nested_cv.py`(v1), `nested_cv_v2.py`(leak-free 조기종료), 산출물 `nested_cv_state.pkl`,
  `nested_cv_v2_state.pkl`.

## 13. L1 정규화 로지스틱회귀로 피처선택 방법을 바꿔 nested CV 재검증 (2026-07-27)

**배경**: 12절에서 greedy SHAP forward selection이 랜덤 수준(AUC 0.47~0.49)으로 붕괴한 것이 "탐색 절차
자체의 불안정성(고분산)" 때문일 수도 있다는 가능성을 배제하기 위해, 훨씬 안정적인 내장 정규화 방식인
**L1 로지스틱회귀(Lasso)**로 피처 선택 방법을 교체해 같은 nested CV 틀에서 재검증.

**방법**: outer-train(139명) 안에서 inner 5-fold로 정규화 강도 C(0.01~3.0, 6개 그리드)를 선택 → 그 C로
outer-train 전체에 L1 로지스틱을 학습해 계수가 0이 아닌 피처만 채택. 두 후보를 평가:
- **후보 A**: L1 로지스틱 자체를 최종 분류기로 사용 (가장 표준적인 저분산 접근)
- **후보 B**: L1이 선택한 피처를 기존 4개 트리모델 앙상블(baseline 하이퍼파라미터)에 그대로 투입

**결과**:
| 방식 | Acc | Prec | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| 기존 non-nested baseline (SHAP, 174명 전체 선택) | 0.7356 | 0.6133 | 0.7302 | 0.6667 | **0.7763** |
| Nested (SHAP greedy forward selection) | 0.54~0.55 | ~0.39 | ~0.43 | ~0.41 | **0.47~0.49** |
| Nested (L1 로지스틱 단독) | 0.5805 | 0.4342 | 0.5238 | 0.4748 | **0.5401** |
| Nested (L1 피처선택 + 트리앙상블) | 0.5747 | 0.3721 | 0.2540 | 0.3019 | **0.5095** |

**해석**:
- L1으로 바꿔도 여전히 **랜덤(0.5)에서 크게 벗어나지 못함** (0.51~0.54). SHAP greedy(0.47~0.49)보다는
  살짝 나아졌지만(즉 greedy 탐색의 고분산 문제가 일부는 맞았음), 174명 규모에서 통계적으로 0.5와
  유의하게 구별된다고 보기 어려운 수준.
- L1도 fold마다 선택한 피처 수가 12개~73개로 들쭉날쭉(C가 0.1~1.0 사이에서 오락가락 선택됨) — 정규화를
  약하게 거는 게 inner CV에서 유리했던 fold가 많았다는 뜻인데, 이는 outer-train 139명 안에서도 "약한
  정규화 + 많은 피처"가 우연히 더 잘 맞는 상황이 반복됐다는 의미로, 애초에 안정적으로 분리해낼 수 있는
  강한 신호가 많지 않다는 정황.
- **두 가지 서로 다른 피처선택 방법(greedy SHAP, L1 정규화)이 독립적으로 같은 결론(랜덤 근처)에
  도달했다는 것은, 이게 특정 방법론의 결함이 아니라 이 데이터/피처 표현 자체의 한계일 가능성을 높임.**
  즉 현재의 patient-level mean/std 집계 피처(222개)로는 174명 규모에서 CN vs MCI+Dementia를 안정적으로
  구분할 만한 신호를 찾기 어렵다는 잠정 결론.

**다음 단계 제안**:
1. ~~더 이상 "피처선택 방법 바꾸기"보다는, 애초에 CV로 아무것도 고르지 않는 극단적으로 단순한 baseline~~
   → **완료, 15절 참고 (2026-07-27) — 역시 랜덤 수준(AUC 0.53)으로 확인, 가장 결정적인 증거**
2. Repeated nested CV(여러 시드 반복)로 지금의 0.47~0.54 범위가 fold 분할의 우연 때문인지 재확인.
3. 반대로 만약 신호가 정말 있다면 표본이 근본적으로 작아서(174명, 그중 이상군 63명) 안정적으로 찾아내기
   어려운 것일 수 있으므로, 데이터 추가 확보(더 많은 환자)가 장기적으로 가장 근본적인 해결책일 수 있음.
- 로컬 스크립트: `nested_cv_l1.py`, 산출물 `nested_cv_l1_state.pkl`.

## 14. Repeated Nested CV — 분할(split)을 바꾸면 성능이 달라지는가? (2026-07-27)

**질문**: 지금까지의 랜덤 근처 결과(0.47~0.54)가 seed=42라는 특정 5-fold 분할의 불운 때문은 아닌지?
분할을 다르게 하면 기존에 보고됐던 0.78 수준이 다시 나올 수도 있지 않은가?

**방법**: L1 로지스틱 단독(13절 후보 A, 가장 실행이 빠르고 결과가 나았던 방식)으로 outer 5-fold의 랜덤
시드를 1~20까지 20개로 바꿔가며 동일한 nested CV(피처선택/threshold는 전부 outer-train 안에서만 결정)를
반복.

**결과**:
| 지표 | 평균 | 표준편차 | 최소 | 최대 |
|---|---|---|---|---|
| AUC | 0.5452 | 0.0417 | 0.4546 | **0.6172** |
| Acc | 0.5408 | 0.0336 | - | - |
| Recall | 0.4992 | 0.1233 | - | - |
| F1 | 0.4342 | 0.0791 | - | - |

20개 분할 중 AUC 0.60 이상은 2개뿐, **0.70을 넘긴 분할은 단 하나도 없었음** (기존 보고치 0.7763에 근접한
분할도 전혀 없음). 반대로 랜덤보다 나쁜(AUC<0.5) 분할도 2개 있었음.

**결론**:
- **분할을 바꿔도 기존에 보고됐던 0.78 수준의 성능은 재현되지 않습니다.** 20번을 서로 다르게 나눠봤지만
  전부 0.45~0.62라는 좁은 밴드 안에 갇혀 있었음 — 즉 0.7763이라는 수치는 "운 좋은 분할"이 아니라
  **애초에 leakage가 만들어낸 수치**였다는 12절의 결론이 다시 한번 확증됨.
- 다만 완전한 "0 신호"도 아님: 평균 0.545가 0.5(랜덤)보다 일관되게 높게 나오는 경향은 있음(20개 중
  18개가 0.5 이상). 표준편차 0.0417, n=20 기준으로 평균이 우연히 0.5로 나올 가능성은 낮아 보이나(반복
  자체가 같은 174명을 재사용하는 것이라 완전히 독립적인 반복은 아니므로 참고용 신호로만 볼 것), 있다 해도
  **아주 약한 신호(AUC 0.54~0.55 수준)** 이지 실용적으로 쓸 만한 진단 성능은 아님.
- **최종 결론**: "분할이 문제였다"가 아니라 "현재 피처 표현 + 174명 규모로는 강한 신호를 찾기 어렵다"는
  12·13절의 결론이 분할 방식과 무관하게 일관됨. 이 프로젝트가 report.docx 등에 공유해온 SOTA AUC
  0.78~0.81 수치는 실제 배포 시 기대할 수 있는 성능이 아니며, 정직한 기대치는 AUC 0.5~0.55 수준(거의
  분별력 없음)에 가까움.
- 로컬 스크립트: `repeated_nested_cv_l1.py`, 결과 `repeated_nested_cv_l1_results.csv` (20개 분할 상세).

## 15. 극단적으로 단순한 baseline — 피처선택 자체를 없앤 검증 (2026-07-27) ★가장 결정적인 증거★

**배경**: 12~14절은 "피처선택 방법(SHAP greedy vs L1)"과 "분할 방식"을 바꿔가며 검증했지만, 여전히
"많은 후보 피처 중에서 자동으로 고르는" 절차 자체가 남아있었음. 이번엔 그 절차 자체를 완전히 제거 —
CV로 아무것도 고르지 않고, 임상적으로 의미가 명확한 피처 5개만 **사전에 고정**해 로지스틱회귀 하나만
평가. 애초에 "고를 것"이 없으므로 leakage가 발생할 여지 자체가 없는, 가장 단순하고 정직한 baseline.

**방법**: 고정 피처 5개 — `activity_average_met`(평균 활동강도), `activity_steps`(평균 걸음수),
`sleep_efficiency`(평균 수면효율), `sleep_score`(평균 수면점수), `activity_score`(평균 활동점수).
StandardScaler(훈련폴드 기준) → SMOTE(훈련폴드만) → LogisticRegression(class_weight='balanced') 하나.
14절과 동일하게 5-fold를 20개의 다른 랜덤 시드로 반복.

**참고 (전체 데이터로 1회 학습한 계수 방향, 성능 평가엔 미사용 — 방향성만 확인)**:
- `activity_average_met`: 이상군일수록 **낮음** (coef -0.586) — 임상적으로 타당한 방향
- `activity_steps`: 이상군일수록 **높음** (coef +0.563) — 다소 직관과 반대(활동량이 오히려 많음)
- `sleep_efficiency`: 이상군일수록 **낮음** (coef -0.411) — 임상적으로 타당한 방향
- `sleep_score`, `activity_score`: 거의 0에 가까운 계수 (coef +0.078, +0.061) — 사실상 무의미

**결과 (20개 분할)**:
| 지표 | 평균 | 표준편차 | 최소 | 최대 |
|---|---|---|---|---|
| AUC | 0.5335 | 0.0401 | 0.4502 | **0.5940** |
| Acc | 0.5514 | 0.0595 | - | - |
| Precision | 0.4519 | 0.1317 | - | - |
| Recall | 0.5841 | 0.2545 | - | - |
| F1 | 0.4545 | 0.1314 | - | - |

**20개 분할 중 AUC 0.60을 넘긴 분할이 단 하나도 없었음** (12~14절의 정교한 nested CV 결과인 0.47~0.62
범위와 거의 동일). 참고로 seed=42의 confusion matrix: `[[18,93],[7,56]]` (Acc=0.4253) — 이는 단순히
"CN(다수 클래스)"으로만 찍는 것(Acc=111/174=63.8%)보다도 낮은 정확도로, 모델이 사실상 거의 무작위에
가깝게 예측하고 있음을 보여줌.

**결론 — 지금까지의 검증 중 가장 결정적인 증거**:
- 12절(SHAP greedy nested), 13절(L1 로지스틱 nested), 14절(20회 반복), 그리고 이번 15절(피처선택 자체를
  제거한 5-피처 고정 baseline)까지 **네 가지 완전히 다른 방법론이 전부 AUC 0.45~0.62라는 같은 좁은
  구간에 수렴**함.
- 이는 "피처선택 방법의 문제"도 "분할의 문제"도 아니라, **이 174명 규모의 웨어러블 활동/수면 데이터에는
  CN vs MCI+Dementia를 구분할 만큼 강한 신호가 (적어도 현재의 patient-level mean/std 요약 방식으로는)
  존재하지 않는다**는 것을 시사함.
- 계수 방향(활동량↓, 수면효율↓ = 이상군) 자체는 임상 문헌과 일치해 완전히 무의미한 데이터는 아니지만,
  효과 크기가 174명 규모에서 안정적으로 분류에 쓸 만큼 크지 않음.
- **최종 권고**: 이 프로젝트의 report.docx 등에 기록된 "SOTA AUC 0.78~0.81"은 리더십/외부에 공유하기 전에
  반드시 정정이 필요함. 실제로 신뢰할 수 있는 성능은 AUC 0.5~0.55 수준(임상적으로 유의미한 분류기라고
  보기 어려움)이며, 이 결론을 뒤집으려면 (a) 근본적으로 다른/더 강력한 피처 표현(예: 원본 시계열을 직접
  다루는 딥러닝 등, 다만 8절에서 daily-level도 약한 신호로 확인됨), 또는 (b) 표본 수를 늘리는 것 중
  하나가 필요해 보임.
- 로컬 스크립트: `simple_baseline.py`, 결과 `simple_baseline_results.csv`.

## 16. CN vs MCI+Dem 이진분류가 MCI 때문에 신호가 희석된 것 아닌가? — 쌍별(pairwise) 재검증 (2026-07-27)
★15절 다음으로 중요한 발견★

**배경**: 사용자가 patient-level 피처 분포 boxplot(CN/MCI/Dem 3그룹)을 직접 검토한 결과, **대부분의 피처에서
CN과 MCI 박스플롯이 거의 완전히 겹치고, Dem만 뚜렷이 갈라지는 패턴**을 발견 (예: `activity_average_met`,
`activity_score`, `sleep_light_ratio_5min`, `activity_rest_ratio`, `activity_daily_movement` 등). 이에
"CN vs MCI+Dem 이진분류가, 사실상 신호가 거의 없는 CN-vs-MCI 문제와 신호가 있을 수도 있는 CN-vs-Dem 문제를
억지로 합쳐놔서, MCI(51명, Dem 12명보다 훨씬 많음)가 신호를 희석시킨 것 아니냐"는 가설을 제기.

**방법**: 15절과 동일한 방법론(피처선택 없이 고정 5개 피처, leakage 없는 5-fold를 20개 시드로 반복)을
174명을 세 그룹으로 나눠 쌍별로 재적용:
- CN(111) vs Dem(12) — 총 123명
- CN(111) vs MCI(51) — 총 162명
- MCI(51) vs Dem(12) — 총 63명

**결과**:
| 비교 | n | AUC 평균 | AUC 표준편차 | AUC≥0.60 반복 수 | AUC≥0.70 반복 수 |
|---|---|---|---|---|---|
| CN vs MCI+Dem (기존, 15절) | 174 | 0.5335 | 0.0401 | 미집계 | 0/20 |
| **CN vs Dem만** | 123 | **0.6334** | 0.0246 | 19/20 | 0/20 |
| **CN vs MCI만** | 162 | **0.5198** | 0.0303 | 0/20 | 0/20 |
| **MCI vs Dem만** | 63 | **0.6965** | 0.0368 | 19/20 | 10/20 |

**해석 — 가설이 확인됨**:
- **CN vs MCI만 따로 보면 AUC 0.52로, 15절의 "완전히 무작위"보다도 못한 수준.** 즉 boxplot에서 관찰된 대로
  현재 피처로는 CN과 MCI가 거의 구분되지 않음. MCI 51명이 "CN과 유사한 애매한 신호"를 대거 포함하고 있음.
- **CN vs Dem, MCI vs Dem은 둘 다 AUC 0.63~0.70으로 15절 대비 뚜렷이 개선됨** (특히 MCI vs Dem은 20번 중
  10번이 0.70을 넘김 — 지금까지의 모든 검증 중 가장 좋은 수치). **Dementia는 실제로 CN/MCI와 어느 정도
  구분 가능한 신호를 갖고 있다는 뜻.**
- 즉 원래의 "CN vs MCI+Dem" 이진분류 설계 자체가 문제였음: 신호가 거의 없는 51명(MCI)을 신호가 있는
  12명(Dem)과 같은 클래스로 묶어버리면서, MCI의 노이즈가 Dem의 신호를 압도해 전체 성능을 0.53까지
  끌어내린 것으로 보임.
- **주의**: Dem은 12명뿐이라 표본이 매우 작음 — confusion matrix 하나(seed=1, CN vs Dem)를 보면 TP=5,
  FN=7로 겨우 12명 중 몇 명이 오분류되느냐에 따라 지표가 크게 흔들림. AUC 0.63~0.70도 "확실히 임상적으로
  유의미하다"고 단정하기엔 이르고, 표본을 늘려 재확인이 필요한 잠정적 신호.

**다음 단계 제안**:
1. 데이터가 허락한다면 Dementia 환자를 더 확보해 CN vs Dem 이진분류를 표본 크게 재검증.
2. 3-클래스(CN/MCI/Dem) 또는 순서형(ordinal) 문제로 재구성하는 것도 고려 가능 — 다만 MCI 51명 자체가
   식별하기 어려운 그룹이라는 게 확인됐으므로, 실용적으로는 "CN vs Dem 스크리닝"에 집중하고 MCI는 별도
   생체지표(MMSE 등)로 보완하는 방향이 더 현실적일 수 있음.
3. CN vs Dem / MCI vs Dem 각각에 대해 (표본이 허락하는 한도 내에서) L1 로지스틱 등으로 피처를 좀 더
   풍부하게 써보는 것도 시도 가능 — 다만 Dem=12로는 CV 기반 피처선택 자체가 극도로 불안정할 위험이 커서
   신중해야 함(12~13절에서 확인한 것처럼 표본이 작을수록 피처선택 leakage/불안정성 문제가 심해짐).
- 로컬 스크립트: `pairwise_groups.py`, 결과 `pairwise_cn_dem.csv`, `pairwise_cn_mci.csv`, `pairwise_mci_dem.csv`.

## 17. "MCI를 정상군에 묶고 Dementia 스크리닝에 집중" 재구성 검증 (2026-07-27)

**배경**: 16절에서 CN vs MCI는 신호가 없고(AUC 0.52), Dementia가 낀 비교만 신호가 있다는 게 확인됨.
사용자가 임상적으로 합리적인 재구성을 제안: 어차피 CN과 MCI를 구분 못한다면, **MCI를 정상군(음성)에
합치고 Dementia만 양성(스크리닝 대상)으로 재정의**하면 어떨까 — 이는 16절의 "CN vs Dem만(MCI 제외)"과
달리 MCI 환자도 데이터셋에 남겨두고 "정상 취급"하는 것이라, 실제 배포 시 "이 사람이 MCI인지 미리 걸러낼
필요 없이 바로 스크리닝에 쓸 수 있다"는 실용적 장점이 있음.

**방법**: 15~16절과 동일 방법론(고정 5피처, leakage 없음, 20회 반복 5-fold). 라벨: CN+MCI(162명, 음성)
vs Dementia(12명, 양성), 총 174명(전체 데이터 그대로 사용).

**결과**:
| 방식 | n | AUC 평균 | 비고 |
|---|---|---|---|
| CN vs MCI+Dem (원래 이진분류) | 174 | 0.5335 | 15절 |
| CN vs Dem만 (MCI 제외) | 123 | 0.6334 | 16절 |
| **CN+MCI vs Dem (MCI를 음성에 포함)** | **174** | **0.6526** | 이번 절 |

AUC 0.6526 (std 0.0301, 20회 중 19회가 0.60 이상, 1회가 0.70 이상) — **MCI를 제외했던 16절(0.6334)보다
오히려 살짝 더 좋거나 최소한 밀리지 않음.** 즉 MCI를 "정상 취급"해서 음성군에 넣어도 신호가 딱히
희석되지 않았음 — 아마 음성군 표본이 111명→162명으로 늘어나면서 모델이 더 안정적으로 학습된 효과가,
MCI가 섞여 들어간 노이즈를 상쇄한 것으로 보임.

**참고 confusion matrix (seed=1, threshold=0.493)**:
| | 예측: 정상 | 예측: 치매 |
|---|---|---|
| 실제: CN+MCI | TN=129 | FP=33 |
| 실제: Dementia | FN=4 | TP=8 |

이 임계값에서 치매 12명 중 8명(67%)을 잡아내고 4명을 놓침, 대신 정상군 162명 중 33명(20%)을 오탐. 20회
반복 평균 Recall(치매 검출율)은 0.5625 — 스크리닝 목적에 맞게 재현율(민감도)을 더 높이는 쪽으로 임계값을
낮추면 오탐(FP)이 늘어나는 대신 놓치는 치매 환자(FN)를 더 줄일 수 있음(V35처럼 recall 제약을 걸고
재최적화하는 것도 가능).

**결론 — 이 재구성이 가장 실용적인 다음 방향**:
- "CN+MCI(정상 취급) vs Dementia" 재구성은 (a) 원래 이진분류(0.53)보다 뚜렷이 낫고, (b) MCI를 데이터셋에서
  제외할 필요가 없어 전체 174명을 그대로 쓸 수 있고, (c) 임상적으로도 "미리 MCI 여부를 알아야 한다"는
  비현실적 전제가 필요 없어 실제 배포에 더 적합함.
- 다만 여전히 Dementia=12명이라는 작은 표본의 한계는 남아있고, AUC 0.65 자체도 임상 스크리닝 도구로
  쓰기엔 아직 부족한 수준(참고로 임상에서 통상 AUC 0.7~0.8 이상을 "쓸만함"의 기준으로 봄). 하지만
  15절의 "사실상 신호 없음"에서 17절의 "약하지만 일관된 신호"로 결론이 개선된 것은 유의미한 진전.
- **다음 세션 권장 방향**: 이 CN+MCI vs Dementia 프레이밍을 정식 다음 실험 축으로 채택. (1) 표본이
  허락하는 한도 내에서 신중하게 피처를 더 추가해보기(단 CV 기반 자동 피처선택은 Dem=12로 인해 여전히
  불안정할 위험이 크므로, 임상적으로 의미가 명확한 피처를 소수 더 추가하는 방식을 권장), (2) recall을
  높이는 방향으로 임계값 재최적화, (3) 무엇보다 Dementia 환자 표본을 추가 확보하는 것이 가장 근본적인
  개선책.
- 로컬 스크립트: `dementia_screening.py`, 결과 `dementia_screening_results.csv`.

## 18. 임상적으로 명확한 피처 5개 추가 (2026-07-27) ★현재까지 가장 좋은 결과★

**배경**: 17절(CN+MCI vs Dementia, 고정 5피처)의 AUC 0.65를 개선하기 위해, CV 기반 자동 탐색(12~14절에서
불안정성이 반복 확인됨) 대신 **문헌 근거가 명확한 피처 5개를 신중하게 사전 지정**해 추가:
- `sleep_deep_ratio_5min` — 깊은 수면(서파수면) 비율 감소는 아밀로이드 청소 저하와 연관, 치매 문헌에서 잘 알려짐
- `activity_daily_movement` — 전반적 이동성
- `sleep_awake_ratio_5min` — 수면 중 각성/분절 비율 (수면의 질 저하 지표)
- `activity_rest_ratio` — 좌식/휴식 비율
- `sleep_hr_5min_std` — 수면 중 심박변이 (자율신경계 조절장애 지표)

(사용자가 직접 검토한 boxplot에서도 이 5개 모두 Dem 그룹이 CN/MCI와 눈에 띄게 갈라지는 것을 사전 확인)

**결과 (CN+MCI vs Dementia, 174명, 20회 반복 5-fold)**:
| 피처셋 | 개수 | AUC 평균 | AUC≥0.60 | AUC≥0.70 |
|---|---|---|---|---|
| 기존 5개 (17절) | 5 | 0.6526 | 19/20 | 1/20 |
| **신규 5개만** | 5 | **0.7198** | 20/20 | 15/20 |

신규 피처 5개만으로도(기존 5개보다 적은 표본 낭비) 기존보다 크게 개선되었고, 20회 중 20회 전부 AUC 0.60을
넘겼으며 14~15회가 0.70을 넘김 — **처음으로 "임상적으로 어느 정도 쓸만하다"는 기준선(AUC 0.7)에
일관되게 도달**.

**참고용 계수 방향 (전체 데이터 1회 학습, 방향성 확인용 — 해석에 주의 필요)**:
| 피처 | 계수 | 방향 | 문헌과 일치? |
|---|---|---|---|
| `sleep_awake_ratio_5min` | +1.054 | 치매일수록 각성↑ | ✅ 일치 (수면 분절 증가) |
| `activity_rest_ratio` | +1.658 | 치매일수록 휴식↑ | ✅ 일치 (활동량 감소), 가장 강한 계수 |
| `sleep_hr_5min_std` | +0.622 | 치매일수록 심박변이↑ | ✅ 일치 (자율신경 조절장애) |
| `sleep_deep_ratio_5min` | -0.091 | 치매일수록 깊은수면↓ | ✅ 방향은 일치하나 계수가 매우 작음(다른 수면 피처와 다중공선성 가능) |
| `activity_daily_movement` | +0.546 | 치매일수록 이동량↑ | ⚠️ **반직관적** |
| `activity_steps`(기존) | +0.767 | 치매일수록 걸음수↑ | ⚠️ **반직관적** |

**해석 — 개선됐지만 해석에는 신중해야 함**:
- 성능 개선 자체는 뚜렷함(0.65→0.71~0.72) — 문헌 기반으로 고른 피처가 실제로 이 데이터에서도 작동함.
- 다만 `activity_daily_movement`/`activity_steps`가 "치매일수록 활동량이 많다"는 반직관적 방향을 보임.
  두 가지 가능한 설명: (a) 치매 환자의 배회(wandering)/초조 행동으로 인한 목적 없는 이동량 증가라는
  임상적으로 알려진 현상을 반영했을 가능성, (b) Dem=12명이라는 작은 표본 + 피처 간 다중공선성으로 계수
  추정이 불안정할 가능성. 현재 데이터로는 둘을 구분할 수 없음 — **표본을 늘리기 전까지는 이 방향성을
  임상적 사실로 단정하지 말 것.**
- 신규 5개만 썼을 때(AUC 0.7198)가 10개 합쳤을 때(0.7128)보다 근소하게 나음 — 기존 5개 중 일부

**다음 단계 제안**:
1. `activity_daily_movement`/`activity_steps`의 반직관적 방향이 진짜인지(배회 행동) 아니면 노이즈인지
   확인하려면 Dementia 표본을 늘려 재검증 필요.
2. 신규 5개 피처만 쓰는 버전(0.7198)을 다음 공식 후보로 채택 고려.
3. Recall(현재 seed=1 기준 12명 중 7명 검출, 나머지는 놓침)을 스크리닝 목적에 맞게 더 높이는 임계값
   재최적화(V35처럼 recall 하한 제약을 걸고 재탐색).

  `dementia_screening_10feat.csv`, `dementia_screening_newonly.csv`.

| 피처셋 | outlier 포함 AUC | outlier 제외 AUC | 변화 |
|---|---|---|---|
| 10개 피처 (18절) | 0.7128 | **0.7830** | +0.070 |
| 신규 5개만 | 0.7198 | **0.7985** | +0.079 |

20회 반복 전부(20/20)가 AUC 0.70을 넘김 (이전엔 14~15/20) — **표본이 173명으로 오히려 하나 줄었는데도
성능과 안정성이 모두 크게 개선됨.**

**계수 방향도 개선됨**:
| 피처 | 포함 시 | 제외 시 |
|---|---|---|
| `activity_daily_movement` | +0.546 (반직관적) | **-0.617 (임상 기대와 일치로 전환)** |
| `activity_steps` | +0.767 (반직관적) | +1.143 (여전히 반직관적, 오히려 강해짐) |

`activity_daily_movement`는 이 한 명을 빼자마자 부호가 정상적으로 뒤집혔지만, `activity_steps`는 여전히
"치매일수록 걸음수 많음" 방향을 유지 — 즉 이 이상치가 문제를 전부 설명하지는 않으며, `activity_steps`
쪽은 다른 이유(다중공선성, 혹은 일부 치매 환자의 배회행동을 반영하는 실제 신호)가 있을 수 있음. 표본이
작아 단정하기는 이름.

**결론**:
- **단 한 명의 이상치 제거만으로 AUC가 0.72 → 0.78~0.80까지 상승** — 지금까지 시도한 모든 방법(피처
  추가, 하이퍼파라미터 튜닝, 문제 재구성 등)을 통틀어 가장 큰 개별 개선 효과.
- 이는 통계적 방법론(nested CV, 정규화 등)만으로는 못 잡아내는 종류의 문제였고, **사람이 직접 샘플을
  들여다보는 정성적 검수(EDA)가 결정적인 역할**을 했다는 것을 보여줌. 12~18절의 모든 정교한 검증이
  "표본이 작아서 신호가 약하다"는 결론에 머물렀던 것도, 부분적으로는 이 이상치 하나가 신호를 흐리고
  있었기 때문일 수 있음.
- Dem=11명으로 더 줄었기 때문에 여전히 매우 작은 표본이라는 근본적 한계는 남아있음. 하지만 방향은
  명확히 옳은 쪽으로 개선됨.

**다음 단계 제안**:
1. `nia+219@rowan.kr`을 실제 프로덕션 파이프라인에서도 이상치로 표시/제외할지 팀 차원에서 결정 필요
   (가능하다면 원본 AIHub 메타데이터나 임상 기록에서 이 환자의 특이사항 확인 권장).
2. 유사한 방식으로 **나머지 173명 전체를 대상으로 이상치 스캔**(예: 각 피처별 Z-score나 IQR 기준 극단치
   점검)을 체계적으로 수행해, 다른 숨은 이상치가 더 있는지 확인.
3. `activity_steps`가 여전히 반직관적인 이유를 더 파보기 (다른 극단치가 남아있는지, 혹은 진짜 배회
   행동을 반영하는 하위 그룹이 있는지).
- 로컬 스크립트: `dementia_screening_v3_exclude_outlier.py`.

## 20. 173명 전체 체계적 이상치 스캔 (2026-07-27)

**방법**: nia+219 제외 후 173명 전체, 218개 raw feature에 대해 robust z-score(median/MAD 기반, 이상치
자체에 덜 민감)로 |z|>4(극단)/|z|>3(다소 극단) 피처 개수를 환자별로 집계.

**그룹별 평균 이상치 점수**:
| 그룹 | 평균 극단피처수(\|z\|>4) | 평균 다소극단(\|z\|>3) |
|---|---|---|
| CN | 5.07 | 8.39 |
| MCI | 4.04 | 6.55 |
| **Dem** | **7.00** | **15.36** |

Dem 그룹이 평균적으로 더 이상치스러움 — 표본이 작은 데다(11명) CN/MCI가 지배하는 전체 분포 기준으로
보면 Dem이 꼬리 쪽에 몰려있다는 뜻이라, 오히려 "Dementia가 실제로 다르다"는 16~19절 결론과 부합하는
긍정적 신호로 해석됨(나쁜 데이터라기보다 진짜 신호일 가능성).

**전체 1~5위 이상치**: `nia+015`(CN), `nia+398`(CN), `nia+396`(CN), `nia+332`(MCI), `nia+182`(MCI) —
주로 수면 중 심박변이(RMSSD) 극단값, `activity_class_valid_count_std`(활동측정 유효치의 일별 변동성)
극단값. 이들은 표본이 큰 CN(111)/MCI(51) 그룹에 속해 개별 환자 하나의 레버리지가 nia+219(Dem, n=12)
때보다 훨씬 작음 — 우선순위 낮음.

**Dem 그룹 내부**: `nia+139`, `nia+196`이 이상치 점수 상위(각각 극단피처 16개, 15개). 상세 확인 결과
nia+219와는 **성격이 다름**:
- `nia+139`: 수면 시작 시각이 오전 9:36(정상 중앙값 저녁 19:38과 정반대), 수면 정렬 점수 극도로 낮음
- `nia+196`: 수면 midpoint 극단적으로 어긋남, 수면시간 12시간(비정상적으로 김)

이는 nia+219("과도하게 건강해 보이는" 이상치)와 반대로, **수면-각성 리듬 역전(day-night reversal /
sundowning)이라는 치매 문헌에 잘 알려진 임상 현상과 부합** — 즉 데이터 오류가 아니라 **중증 치매의
진짜 증상을 반영하는 극단값일 가능성이 있어, nia+219처럼 단순 제외하면 안 될 수 있음**.

**공통으로 걸리는 피처**: `activity_class_valid_count_std`(활동 유효측정치의 일별 변동성)가 상위 이상치
5명 중 4명(398/332/182/139/196)에서 공통으로 극단적 — 기기 착용의 일관성 문제로 보이며, 데이터 품질
이슈인지 환자의 자기관리 능력 저하를 반영하는 실제 신호인지 판단이 애매해 추가 조사가 필요.

**결론 및 다음 단계**:
- nia+219와 달리 nia+139/nia+196은 곧바로 제외하기보다, 임상 지식이 있는 팀원과 상의해 "진짜 증상"인지
  "데이터 결함"인지 판단 필요.
- `activity_class_valid_count_std`처럼 여러 이상치 환자에서 공통으로 튀는 피처는 데이터 품질 자체를
  점검할 필요(원본 AIHub 데이터의 착용시간/결측 처리 방식 재검토).
- CN/MCI 쪽 상위 이상치(nia+015 등)는 표본이 커서 개별 영향력이 작지만, 전체 EDA 품질을 위해 시간이
  될 때 검토 권장.
- 로컬 스크립트: `outlier_scan.py`, 결과 `outlier_scan_summary.csv` (173명 전체 이상치 점수).

## 21. nia+139/nia+196 포함 vs 제외 — nia+219와 정반대 결론 (2026-07-27)

**질문**: 20절에서 발견한 Dem 그룹 내 이상치 후보 nia+139/nia+196도 nia+219처럼 제외하면 성능이
좋아지는가? (nia+219와 달리 수면리듬 역전이라는 진짜 증상일 수 있다는 가설을 성능으로 검증)

**방법**: 19절 기준선(173명, nia+219만 제외)에서 nia+139/nia+196을 각각 또는 함께 추가로 제외해
20회 반복 5-fold로 AUC 비교 (신규5개 피처, 10개 피처 두 세트 모두).

**결과**:
| 시나리오 | n | Dem | AUC(신규5개) | AUC(10개) |
|---|---|---|---|---|
| 기준(173명, 219만 제외) | 173 | 11 | **0.7985** | **0.7830** |
| 139만 추가 제외 | 172 | 10 | 0.7911 | 0.7678 |
| 196만 추가 제외 | 172 | 10 | 0.7847 | 0.7682 |
| 139+196 둘 다 제외 | 171 | 9 | 0.7615 | 0.7273 |

**결론 — nia+219와 정반대**: nia+219를 뺐을 땐 성능이 크게 좋아졌지만(0.72→0.80), **nia+139/nia+196을
빼면 오히려 일관되게 나빠짐** (둘 다 빼면 신규5개 기준 0.7985→0.7615로 -0.037, 10개 기준
0.7830→0.7273으로 -0.056). 하나만 빼도, 둘 다 빼도 같은 방향(감소)으로 단조적으로 나빠짐.

이는 20절의 정성적 판단(nia+219는 "과도하게 건강해 보이는" 데이터 결함 의심 / nia+139·196은
"수면-각성 리듬 역전"이라는 문헌상 잘 알려진 치매 증상)을 **성능으로도 뒷받침함**: 통계적으로는 셋 다
"이상치"로 잡혔지만, 실제로는 성격이 완전히 다른 두 부류였고 — 한쪽(219)은 제거해야 할 노이즈, 다른
쪽(139/196)은 모델에 필요한 진짜 신호였음.

**시사점**: "이상치 = 무조건 제거"가 아니라, **왜 이상치인지 임상적 맥락과 함께 판단하고, 제거 여부를
실제 성능으로 검증하는 절차가 중요함**을 보여주는 좋은 사례. 앞으로 유사한 이상치 후보가 나오면
(1) 정성적으로 그럴듯한 원인이 있는지, (2) 제외 시 실제 성능이 개선되는지 두 가지를 모두 확인할 것.

**최종 권고**: nia+219는 제외 유지, nia+139/nia+196은 **포함 유지**(19절의 173명, Dem 11명 기준선이
현재까지 최선의 설정). 최종 성능: **AUC 0.7985 (신규 5개 피처: sleep_deep_ratio_5min,
activity_daily_movement, sleep_awake_ratio_5min, activity_rest_ratio, sleep_hr_5min_std)**.
- 로컬 스크립트: `dementia_screening_v4_139_196.py`.

## 22. 최선 설정을 LightGBM으로 재검증 — 로지스틱회귀가 더 나음 (2026-07-27)

**배경**: 21절에서 확정된 최선 설정(173명, nia+219만 제외, CN+MCI vs Dementia, 신규 5개 고정 피처,
로지스틱회귀 AUC 0.7985)을 더 강력한 모델(LightGBM)로도 재현되는지 확인. 피처는 여전히 고정(자동
CV선택 없음)이므로 모델 구조만 바꾸는 것은 leakage 위험이 없어 안전하게 시도 가능. 조기종료는
outer-test를 건드리지 않는 내부 validation split으로 leak-free하게 구현(과적합 방지를 위해 얕은 트리:
num_leaves=7, max_depth=3 등 보수적 하이퍼파라미터 사용).

**결과**:
| 모델 | 피처 | AUC 평균 | AUC 표준편차 | AUC 범위 |
|---|---|---|---|---|
| 로지스틱회귀 (21절 기준선) | 신규 5개 | **0.7985** | 0.0205 | 좁음 |
| **LightGBM** | 신규 5개 | 0.7429 | **0.0560** | 0.58~0.81 (넓음) |
| 로지스틱회귀 | 10개 | 0.7830 | 0.0224 | 좁음 |
| **LightGBM** | 10개 | 0.7163 | 0.0512 | 0.63~0.80 (넓음) |

**결론 — LightGBM이 오히려 더 나쁨**: 두 피처셋 모두에서 LightGBM이 로지스틱회귀보다 AUC가
0.055~0.067 낮고, **표준편차는 약 2.5~2.7배 더 큼**(0.021→0.056, 0.022→0.051) — 즉 트리 모델이
성능도 낮고 시드(분할)에 따라 훨씬 더 불안정함.

**해석**: 이는 이 세션 전체를 관통하는 교훈(12~14절: 표본이 작을수록 복잡한 방법이 더 불안정)과
일치함. 양성 클래스(Dementia)가 9~11명뿐인 상황에서는 LightGBM처럼 파라미터가 많고 유연한 모델은
아무리 보수적으로 정규화해도(얕은 트리, L1/L2, leak-free 조기종료) 로지스틱회귀 5개 계수만큼 안정적으로
추정되지 않음 — **분산(variance)이 편향(bias) 감소보다 훨씬 크게 증가하는 전형적인 bias-variance
트레이드오프**. 참고 confusion matrix(LightGBM 신규5개, seed=1): `[[141,21],[4,7]]` — 로지스틱회귀와
비슷한 수준의 재현율이지만 전반적으로 더 불안정.

**최종 권고**: 이 표본 규모(173명, 양성 11명)에서는 **로지스틱회귀 + 신규 5개 고정 피처(AUC 0.7985)가
여전히 최선의 설정**. LightGBM 등 트리 앙상블은 표본이 지금보다 충분히 늘어난(예: Dementia 환자
30명 이상) 이후에 재시도하는 것을 권장 — 지금 시도하는 것은 시기상조.
- 로컬 스크립트: `dementia_screening_lgbm.py`, 결과 `dementia_screening_lgbm_new5.csv`,
  `dementia_screening_lgbm_10feat.csv`.

## 23. MMSE(인지기능검사) 추가 검증 (2026-07-27)

**⚠️ 해석 주의**: MMSE는 웨어러블 신호와 달리 **임상적으로 치매/MCI 진단을 내리는 데 직접 쓰이는 검사**임
(4절 V41 노트북에서도 "정답 누설에 가까운 피처"로 지적됨). 성능이 크게 오르는 것은 당연하며, 이는
"웨어러블만으로 치매를 잡아낼 수 있는가"라는 이 프로젝트의 원래 질문과는 별개의 참고 지표로 봐야 함.

**방법**: 21절 최선 설정(173명, nia+219 제외, CN+MCI vs Dementia, 로지스틱회귀)에 `train_mmse.csv` +
`val_mmse.csv`의 `TOTAL`(MMSE 총점, 0~30) 병합. 결측치 없음(173명 전원 매칭). 그룹별 MMSE 평균:
CN 27.7 / MCI 25.8 / Dem 16.0(표준편차 8.15, 매우 넓게 퍼짐) — 예상대로 뚜렷한 분리.

**결과**:
| 피처셋 | AUC | Acc | Prec | Recall | F1 |
|---|---|---|---|---|---|
| 웨어러블 5개만 (21절 기준선) | 0.7985 | 0.8488 | 0.2860 | 0.7682 | 0.4088 |
| **MMSE만 (1개 피처)** | **0.9155** | 0.9116 | 0.4243 | 0.8727 | 0.5645 |
| 웨어러블5 + MMSE (6개) | 0.8717 | 0.9460 | 0.5661 | 0.8045 | 0.6610 |

**흥미로운 점 — MMSE 단독이 웨어러블+MMSE 조합보다도 더 나음**: 6개를 합친 것(0.8717)보다 MMSE
하나만 쓴 것(0.9155)이 AUC가 더 높음. 이는 22절(LightGBM)과 같은 맥락 — 표본이 극히 작을 때(양성 11명)는
피처를 하나 더 추가하는 것만으로도(설령 그 피처가 약한 신호라도) 파라미터 추정의 분산이 늘어나
오히려 손해가 될 수 있음. 다만 Accuracy/F1은 조합이 더 높게 나와(0.946/0.661) 지표별로 결론이 다소
엇갈림 — 표본이 작아 이 차이 자체도 불확실성이 큼.

**계수 방향(참고용, 전체데이터 1회 학습)**: `MMSE_TOTAL` coef=-2.270(치매일수록 MMSE 낮음, 매우 강한
계수 — 다른 웨어러블 피처 계수(0.001~1.502)보다 압도적으로 큼), 웨어러블 피처들의 계수는 18절/19절과
거의 동일한 방향 유지.

**결론**: MMSE를 넣으면 성능은 크게 오르지만(AUC 0.80→0.92), 이는 "진단 기준 자체를 입력에 포함시킨"
결과에 가까워 웨어러블 기반 스크리닝의 가치를 보여주는 지표로는 부적절함. 오히려 이번 실험의 핵심
시사점은 **"강한 피처 하나(MMSE)를 여러 약한 피처와 섞으면 오히려 성능이 떨어질 수 있다"**는
재확인 — 표본이 작을 땐 피처 개수를 늘리는 것 자체가 위험 부담이라는 이 세션의 핵심 교훈이 MMSE
사례에서도 그대로 나타남. 웨어러블 단독 스크리닝의 정직한 성능은 여전히 21절의 AUC 0.7985.
- 로컬 스크립트: `dementia_screening_mmse.py`, 결과 `dementia_screening_mmse_wearable.csv`,
  `dementia_screening_mmse_only.csv`, `dementia_screening_mmse_combined.csv`.

## 24. SHAP 기반 K=1~15 leak-free 스윕에서 발견한 압도적 단일 피처 `activity_low_std`

## 26. Threshold(임계값) 선택에도 leakage가 있었음을 사용자가 발견 — 정정 (2026-07-27)

**배경**: 사용자가 "이거 그 데이터누수 없을 때의 성능 맞지?"라고 질문. 점검해보니, 21~25절에서 계속 쓴
`run_one_seed`류 함수들은 **feature selection은 leak-free였지만(12~14절에서 고친 부분), threshold는
아니었음** — Youden's J 임계값을 "20회 반복의 OOF 예측값을 전부 모아놓고 그중에서 가장 잘 맞는 지점"으로
골랐는데, 이는 평가에 쓰는 바로 그 데이터를 보고 임계값을 고른 것이라 약한 낙관적 편향이 있었음.

**검증**: 12~13절의 nested CV 구조(threshold도 outer-train 안에서 inner-CV로만 결정)를 이번엔 threshold
선택에도 적용해 재계산.

| 모델 | 버전 | ROC-AUC | Accuracy | Precision | Recall | Specificity | F1 |
|---|---|---|---|---|---|---|---|
| activity_low_std 단독 | 낙관적(이전) | 0.9091 | 0.8387 | 0.2691 | 0.8955 | 0.8349 | 0.4139 |
| activity_low_std 단독 | **완전 leak-free** | 0.9087 | 0.8514 | 0.2749 | **0.8136** | 0.8540 | 0.4108 |
| activity_low_std+MMSE | 낙관적(이전) | 0.9539 | 0.9679 | **0.7224** | 0.8045 | 0.9790 | **0.7613** |
| activity_low_std+MMSE | **완전 leak-free** | 0.9545 | 0.9098 | **0.4403** | 0.7682 | 0.9194 | **0.5396** |

**결론**:
- **ROC-AUC는 threshold 선택과 무관하므로 항상 정확했음** (0.9091 vs 0.9087, 0.9539 vs 0.9545 — 차이는
  랜덤 변동 수준).
- **1개 피처(activity_low_std) 모델은 영향이 작음** — Recall이 0.90→0.81로 다소 하락했지만 나머지는
  거의 그대로. 임계값 하나(자유도 1개)만의 문제라 영향이 제한적.
- **2개 피처(activity_low_std+MMSE) 조합은 영향이 훨씬 큼** — Precision 0.72→0.44, F1 0.76→0.54로
  큰 폭 하락. 피처 수가 늘어난 것(22~24절의 "많을수록 소표본에서 과대평가" 패턴)과 threshold leakage가
  겹쳐 효과가 증폭됨.
- **교훈**: leakage를 "피처 선택"에서만 조심하고 "임계값 선택"은 간과하기 쉬움. 어떤 결정(피처, 하이퍼
  파라미터, 임계값 등)이든 **평가 데이터의 라벨을 들여다보고 고른 것이라면 전부 같은 방식으로 오염됨**.
  이 세션에서 배운 "leak-free 원칙"은 모델 선택뿐 아니라 최종 운영점(operating point) 결정에도 똑같이
  적용해야 함.
- **25절의 최종 확정 모델 표는 이 절의 완전 leak-free 수치로 교체 완료.**
