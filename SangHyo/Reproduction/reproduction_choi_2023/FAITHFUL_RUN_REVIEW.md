> **[2026-08-15 정정]** 이 절의 초판에 "Voting이 최고라는 논문의 헤드라인 구조는
> 유지된다"고 적었으나 **사실과 다르다**. 재현의 1위는 stacking(0.9091)이고 voting은
> 2위(0.9052)다. 아래 순위 분석으로 대체한다.

**순위 구조 (AUC 내림차순)**

| 순위 | 논문 | 재현 |
| --- | --- | --- |
| 1 | voting .9193 | **stacking .9091** |
| 2 | gbc .9161 | voting .9052 |
| 3 | xgboost .9132 | xgboost .8972 |
| 4 | lightgbm .8971 | lightgbm .8913 |
| 5 | et .8877 | et .8756 |
| 6 | rf .8781 | rf .8736 |
| 7 | stacking .6539 | **gbc .8684** |

- 7개 전체 순위 상관 Spearman **−0.107** (stacking과 gbc가 양 끝에서 자리를 맞바꿔
  상관이 무너진다). 반면 **base 4종(xgboost·lightgbm·et·rf)의 순서는 완전 일치
  (Spearman 1.000)**이며 값도 −0.006 ~ −0.016 이내다.
- 검증 가능한 사실만 적으면: 재현에서 voting은 **base 5종 최고(xgboost 0.8972)보다
  +0.0081 높지만**, stacking보다 0.0039 낮다. 따라서 논문 주장 "Voting이 최고"는
  **재현되지 않았다**(단, voting과 stacking의 차이 0.0039는 두 값 모두 0.90대라
  실질적 우열로 보기 어려운 크기다 — 아래 §8의 시드 변동 측정 참조).
- **gbc(−0.0477)가 base 모형 중 최대 편차**다. Table 5에서 논문의 랜덤서치는 GBC를
  CV 0.7986 → 0.9061로 올렸고 재현은 0.7986 → 0.8737에 그쳤다(출발점은 소수
  넷째 자리까지 동일). 이 CV 차이가 홀드아웃으로 전파된 것으로 **관측**된다.
- **stacking은 여전히 붕괴하지 않는다**(0.9091 vs 논문 0.6539). 이 항목은 1차 재현의
  2×2 실험에서 이미 규명됐다: 같은 파이프라인을 5회(C fold) 돌렸을 때 stacking AUC가
  0.59~0.88로 요동쳤고 논문 값이 그 범위 안에 들어왔다. **방법의 성질이 아니라
  실행 간 불안정성**이라는 결론이 이번 실행으로 한 번 더 지지된다.

## 7. 실행 중 발생한 문제와 조치

**문제**: 학습 셀이 45분을 다 돌고 **manifest 저장 직전 `NameError: RUNTIME_VERSIONS`**로
중단됐다. 세션 재시작 후 환경 검증 셀(RUNTIME_VERSIONS 정의 지점)을 건너뛰고 설정
셀부터 실행하면 발생하는, 노트북 설계 결함이다. 사용자가 저장 블록을 수동 셀로 복사해
실행하여 결과는 온전히 보존됐다.

**조치** (노트북 소스 수정, 기존 출력은 전부 보존):

1. 설정 셀이 `RUNTIME_VERSIONS`를 자체적으로 확정하도록 변경 — 환경 검증 셀을
   건너뛰어도 저장이 실패하지 않는다
2. manifest의 versions를 `globals().get(...)`로 방어
3. Table 6 그림의 범례가 막대를 가리던 문제 수정(그림 하단으로 이동)
4. 사용자가 추가한 복구 셀은 주석과 함께 보존(재실행 시 불필요, 삭제해도 무방)

**미실행 셀**: 시각화 셀(마지막)이 실행되지 않아 `figures/`가 비어 있었다. 저장된
CSV로 동일 그림 4종을 생성해 넣었다(`fid_table4/6/7.png`, `fid_improvement.png`).
