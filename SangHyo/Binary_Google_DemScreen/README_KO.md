# Binary_Google_DemScreen — 치매 스크리닝 (CN+MCI vs Dem) + Google YDF

Hyunsoo의 **문제 재정의** 아이디어를 SangHyo 폴더의 평가 체계로 옮기고, 모델을
**Google YDF** 중심으로 다시 구성한 실험입니다.

> ⚠️ **이 폴더의 수치를 다른 Binary 폴더와 직접 비교하지 마세요.** 문제가 다릅니다.

---

## 1. 다른 폴더와 무엇이 다른가 — 라벨 정의

| | 이 폴더 | 다른 Binary 폴더 |
|---|---|---|
| 양성 | **Dem (12명)** | MCI + Dem (63명) |
| 음성 | CN + MCI (162명) | CN (111명) |

**같은 MMSE 총점 하나**로 두 문제를 풀면 이렇게 갈립니다 (실측):

| 문제 정의 | ROC-AUC |
|---|---|
| 이 폴더: CN+MCI vs Dem | **0.947** |
| 다른 폴더: CN vs MCI+Dem | **0.733** |
| (참고) CN vs MCI만 | 0.677 |

진단군별 MMSE 평균이 **CN 27.7 / MCI 25.8 / Dem 16.6**입니다. 치매는 압도적으로
분리되지만 MCI는 정상과 거의 겹칩니다. 즉 **이 폴더에서 높은 숫자가 나오는 것은
모델이 좋아서가 아니라 문제가 쉬워서**입니다. `train.py`가 이 비교표를 리포트에
자동으로 기록하므로, 결과 파일만 봐도 두 과제가 혼동될 일이 없습니다.

---

## 2. Hyunsoo 방식에서 가져온 것과 바꾼 것

### 가져온 것
- **문제 재정의**: CN vs MCI가 사실상 구분 불가(AUC 0.68)라면, 임상적으로 의미 있는
  치매 탐지로 문제를 다시 세우는 것이 합리적입니다.
- **작은 모델이 이긴다**: Dem 11~12명 규모에서 LightGBM·다중 피처 조합이 단일 피처
  로지스틱회귀보다 나빴다는 관찰. 이건 저희 쪽 `Binary_Google_MaxAUC_Tuned` 결과
  (151피처 + 10시간 튜닝 = 0.7172 < 39피처 무튜닝 = 0.7657)와 **완전히 일치**합니다.
- **임계값도 중첩**: Hyunsoo가 스스로 발견한 threshold leakage를 처음부터 반영했습니다.
- **`univariate` 학습기**: 폴드 안에서 최고 단변량 피처 1개를 골라 로지스틱회귀 —
  Hyunsoo 최종 모델을 이 폴더의 평가 체계 안에서 그대로 재현한 것입니다. 동일 조건
  비교가 가능합니다.

### 바꾼 것 (중요)
**이상치 제외 방식**입니다. Hyunsoo 코드는 치매 환자 1명(`nia+219`)을 제외하는데,
근거가 *"제외 시 AUC가 뚜렷이 개선됨"*입니다. 제가 재현해보니:

| | ROC-AUC | 95% CI |
|---|---|---|
| 이상치 포함 (Dem 12) | 0.845 | [0.669, 0.961] |
| 이상치 제외 (Dem 11) | 0.918 | [0.841, 0.972] |

제외가 **+0.073**을 만들고, 그 1명은 양성의 8.3%입니다. **지표를 보고 제외 대상을
고르는 것은 테스트셋에 튜닝하는 것과 같은 종류의 오류**이고, 이는 Hyunsoo 본인이
로그 26절에서 정리한 원칙 — *"어떤 결정이든 평가 데이터의 라벨을 들여다보고 고른
것이라면 전부 같은 방식으로 오염됨"* — 에 정확히 걸립니다.

그래서 이 폴더는 **라벨을 보지 않는 사전 정의 규칙**만 씁니다 ([data.py](data.py)의
`QUALITY_RULES`):
- `일 평균 25,000보 초과` — 장기 지속이 어려운 값(기기 오사용/기록 오류 가능)
- `착용 일수 7일 미만` — 일별 변동성 피처를 신뢰할 수 없음

그리고 **제외한 결과와 안 한 결과를 둘 다 보고**합니다. 좋은 쪽을 고르지 않습니다.
(참고로 위 규칙은 label을 전혀 보지 않지만 결과적으로 같은 환자를 걸러냅니다 —
차이는 "왜 뺐는가"의 근거가 지표가 아니라는 점입니다.)

## 3. 2×2 설계 — 네 가지를 항상 함께 보고

| | 전체 코호트 (174) | 품질 필터 적용 |
|---|---|---|
| **웨어러블만** | **헤드라인** | 민감도 분석 |
| 웨어러블 + MMSE | 참고(상한) | 민감도 분석 |

- **웨어러블만이 헤드라인**인 이유: "인지검사 없이 손목 기기만으로 치매를 선별할 수
  있는가"가 실제로 가치 있는 질문이기 때문입니다.
- **+MMSE는 참고용**: MMSE는 이 진단을 내리는 **검사 도구 자체**라, 그걸로 진단을
  예측하는 건 스크리닝이라기보다 라벨을 다시 읽는 것에 가깝습니다. Hyunsoo 로그도
  같은 취지로 경고하고 있습니다(23절).

## 4. 모델 — Google YDF 중심, 단 전부 작게

| 학습기 | 설명 |
|---|---|
| `univariate` | 폴드 내 최고 단변량 피처 1개 + 로지스틱회귀 (Hyunsoo 재현) |
| `logreg` | L2 로지스틱회귀, 폴드 내 선택 소수 피처 |
| `ydf_gbt` | **Google YDF** GBT — depth 2, 120트리, L2=5.0로 강하게 규제 |
| `ydf_rf` | **Google YDF** Random Forest — depth 3 |
| `ydf_gbt_oblique` | **YDF sparse oblique** GBT |

oblique를 남긴 이유는 `Binary_Google_MaxAUC_Tuned`에서 개별 학습기 중 1위였기
때문입니다(inner AUC 0.789 vs 축정렬 0.745).

**탐색은 기본적으로 끕니다.** 양성 12명에서 하이퍼파라미터 탐색은 노이즈를 맞추는
쪽에 가깝습니다(MaxAUC_Tuned에서 실측: fold별 `top_k`가 `[70,10,70,10,70,15,0,...]`로
전혀 수렴하지 않았고 inner-outer 격차 +0.053). 컴퓨트는 **탐색 대신 반복(repeats)**에
씁니다. 비교하고 싶으면 `DEMSCREEN_SEARCH=1`로 켤 수 있습니다.

**SMOTE도 기본 꺼짐.** 학습 폴드의 양성이 ~9명이면 합성 샘플은 같은 소수 환자들
사이의 보간이라, 도움보다 분리도를 부풀릴 위험이 큽니다. `DEMSCREEN_SMOTE=1`로 켜서
중첩 평가가 직접 답하게 할 수 있습니다.

## 5. 평가 프로토콜

```
반복 R회 (기본 20):
  바깥 5-fold (subject 단위)
    └ 학습 부분만 사용:
        · 피처 선택 (폴드 내 재계산)
        · 학습기별 설정 + 앙상블 가중치 (inner OOF AUC)
        · 운영 임계값 (inner OOF에 Youden's J)   ← threshold leakage 차단
    └ 테스트 부분: 최종 예측 1회
  반복 안에서 OOF를 모아 1회 채점
→ R회 평균 ± 표준편차 + subject 부트스트랩 95% CI
```

반복 간 표준편차와 부트스트랩 CI를 **둘 다** 보고합니다. 전자는 분할 노이즈,
후자는 표본 노이즈이고, **양성 12명에서는 후자가 압도적**입니다. 점추정치만 읽으면
안 됩니다.

## 6. 실행 (학습은 사용자가 Colab에서)

```
USER_FOLDER = "SangHyo"
RUN_FILE    = "Binary_Google_DemScreen/run.py"
```

**런타임: CPU (High-RAM), GPU 아님.** 모델이 전부 작아서 빠릅니다.

| 모드 | 예상 시간 | 반복 |
|---|---|---|
| `smoke` | ~1분 | 2 (배선 확인용, 지표 무의미) |
| `standard` | ~10분 | 10 |
| **`full`** | **~25분** | **20 (기본, Hyunsoo 프로토콜과 동일)** |

```
DEMSCREEN_MODE=full
DEMSCREEN_SEARCH=1     소규모 그리드 탐색 켜기
DEMSCREEN_SMOTE=1      SMOTE 켜기
DEMSCREEN_KINDS=a,b    학습기 제한
```

## 7. 한계 (리포트에도 자동 기록됨)

- **양성 12명.** 부트스트랩 CI 폭이 0.13~0.29입니다. 소수점 둘째 자리는 의미가 없습니다.
- **홀드아웃 테스트셋이 없습니다.** Dem이 12명뿐이라 train/val을 합쳐 교차검증합니다.
  이건 감춰야 할 게 아니라 명시해야 할 설계 제약입니다.
- **+MMSE 결과는 부분적으로 순환적**입니다.
- 재현성 확인의 최우선 과제는 모델 개선이 아니라 **치매 표본 확대**입니다.

## 8. 파일 구성

| 파일 | 역할 |
|---|---|
| `data.py` | 174명 코호트 + 3-class 진단 + 라벨 무관 품질 규칙 |
| `learners.py` | univariate / logreg / YDF(GBT·RF·oblique), SMOTE 옵션 |
| `spaces.py` | 사전 지정 설정 (탐색은 opt-in) |
| `engine.py` | 반복 중첩 CV + 중첩 임계값 + 부트스트랩 CI |
| `train.py` | 2×2 설계 실행 + 과제 난이도 비교표 기록 |
| `run.py` | base.ipynb 진입점 |

피처 생성과 YDF 래퍼는 `Binary_Google_MaxAUC_Tuned`의 감사 완료된 모듈을 재사용합니다
(151개 피처: MMSE 39 + 웨어러블 112, 원형통계 일주기 규칙성 포함).
